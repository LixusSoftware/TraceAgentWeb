# Despliegue con Docker

TraceAgent ofrece imágenes de Docker ya construidas para el servidor y la UI.

## Imágenes

| Componente | Imagen |
|-----------|-------|
| Servidor | `ghcr.io/lixussoftware/trace-agent-server:0.5.0` |
| UI | `ghcr.io/lixussoftware/trace-agent-ui:0.5.0` |

| Puerto | Componente |
|------|-----------|
| `8000` | API del servidor (y receptor OpenTelemetry) |
| `8080` | UI |

Las imágenes se publican con los tags `0.5.0` (versión exacta), `0.5` (actualizaciones de parche) y `latest`. Usa la **misma versión** para el servidor y la UI, y fija `0.5.0` en producción. `latest` no se vuelve a descargar solo: `docker compose up` reutiliza tu copia local, así que ejecuta `docker compose pull` (o pon `pull_policy: always`) para actualizar. Consulta [TraceAgent en producción](/es/docs/configuration/production).

## Docker Compose

Crea un `docker-compose.yml` para ejecutar los dos servicios:

```yaml title="docker-compose.yml"
version: "3.8"

services:
  server:
    image: ghcr.io/lixussoftware/trace-agent-server:0.5.0
    ports:
      - "8000:8000"
    environment:
      - TRACE_AGENT_DATABASE_URL=sqlite:///./data/trace_agent.db
      - TRACE_AGENT_AUDIT_METRICS_ENABLED=true
    volumes:
      - trace-data:/app/data

  ui:
    image: ghcr.io/lixussoftware/trace-agent-ui:0.5.0
    ports:
      - "8080:8080"
    environment:
      - TRACE_AGENT_SERVER_URL=http://server:8000
    depends_on:
      - server

volumes:
  trace-data:
```

```bash
docker compose up -d
```

La UI estará disponible en `http://localhost:8080` y la API del servidor en `http://localhost:8000`.

## Receptor OpenTelemetry

El contenedor del servidor también recibe trazas OpenTelemetry por el mismo puerto, en `http://localhost:8000/v1/traces`. No hace falta ningún puerto ni servicio adicional: apunta el exportador OTLP de tu agente a esa URL. Consulta la [ingesta OpenTelemetry](/es/docs/instrumentation/opentelemetry).

Para ajustar o desactivar el receptor, añade estas variables al `environment` del servicio `server`:

```yaml
    environment:
      - TRACE_AGENT_OTLP_ENABLED=true
      - TRACE_AGENT_OTLP_MAX_BODY_BYTES=10000000
```

## Con PostgreSQL

Para despliegues en producción, usa PostgreSQL en lugar de SQLite:

```yaml title="docker-compose.prod.yml"
version: "3.8"

services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: traceagent
      POSTGRES_USER: traceagent
      POSTGRES_PASSWORD: changeme
    volumes:
      - pg-data:/var/lib/postgresql/data

  server:
    image: ghcr.io/lixussoftware/trace-agent-server:0.5.0
    ports:
      - "8000:8000"
    environment:
      - TRACE_AGENT_DATABASE_URL=postgresql://traceagent:changeme@db:5432/traceagent
    depends_on:
      - db

  ui:
    image: ghcr.io/lixussoftware/trace-agent-ui:0.5.0
    ports:
      - "8080:8080"
    environment:
      - TRACE_AGENT_SERVER_URL=http://server:8000
    depends_on:
      - server

volumes:
  pg-data:
```

:::danger
Cambia el `POSTGRES_PASSWORD` por defecto antes de desplegar en producción.
:::

:::warning[Antes de usar PostgreSQL]
La imagen del servidor no incluye un controlador de PostgreSQL: tienes que añadir uno (por ejemplo `psycopg`). Las pruebas del proyecto se ejecutan sobre SQLite y no hay migraciones, así que un cambio de esquema en una versión nueva no actualiza una base de datos existente. Consulta [TraceAgent en producción](/es/docs/configuration/production).
:::

# Abre la UI

# Preguntas frecuentes

## General

### ¿Qué es TraceAgent?

TraceAgent es una plataforma de observabilidad y trazabilidad para agentes de IA. Captura llamadas a herramientas, operaciones con archivos, comandos de shell y rutas de decisión, y te da visibilidad completa de lo que hacen tus agentes.

### ¿TraceAgent es de código abierto?

Sí. TraceAgent se publica bajo la **licencia MIT**. Puedes encontrar el código fuente en [GitHub](https://github.com/LixusSoftware/TraceAgent).

### ¿Qué versiones de Python son compatibles?

TraceAgent requiere **Python 3.11+**.

## Pydantic AI y OpenTelemetry

### ¿Puedo usar la capacidad y OpenTelemetry en el mismo agente?

No, elige una por agente. Las dos registran cada llamada al modelo y cada herramienta y no se conocen entre sí, así que la ejecución aparecería duplicada. La única combinación válida es crear la ejecución con el SDK y dejar que OpenTelemetry aporte los spans. Consulta [¿Hooks u OpenTelemetry?](/es/docs/instrumentation/hooks-vs-opentelemetry).

### ¿TraceAgent ralentiza o rompe mi agente si el servidor está caído?

No. Los eventos se encolan y los envía un hilo en segundo plano. Tras un fallo de entrega, la integración se pausa durante `failure_cooldown` segundos, imprime una línea de aviso y mantiene el agente en marcha. Con OpenTelemetry, el exportador envía los spans en segundo plano y solo registra un aviso si no llega al servidor.

### ¿Se guardan mis prompts y salidas?

El servidor guarda un resumen de cada prompt y de cada salida. Con `TRACE_AGENT_CAPTURE_FULL_PAYLOADS` activo (el valor por defecto) también guarda el contenido completo; ponlo a `false` para conservar solo los resúmenes. Con OpenTelemetry, además, puedes impedir que el contenido salga del agente con `include_content=False`. Con la capacidad, usa `redact_fields` para las claves sensibles.

### ¿Qué versiones de Pydantic AI son compatibles?

Pydantic AI 2.x (`>=2,<3`). Para OpenTelemetry, se admite la versión de instrumentación por defecto de Pydantic AI 2.x. Las versiones de instrumentación anteriores (2 a 4) usan nombres de span distintos y no se traducen.

### ¿Tiene el servidor autenticación?

No. El servidor no comprueba ninguna credencial, así que cualquiera que pueda llegar a su API puede leer y escribir ejecuciones. Ejecútalo en una red privada o detrás de un proxy inverso que exija autenticación. Consulta [TraceAgent en producción](/es/docs/configuration/production).

### ¿Puedo agrupar ejecuciones en sesiones o proyectos?

Todavía no, y tampoco puedes filtrar por `metadata`. Una solución práctica es poner el id de sesión en el nombre del agente o al principio del objetivo, y filtrar después con `agent_name` o `search`. Consulta [Ejecuciones, metadatos y búsqueda](/es/docs/core-concepts/runs).

### ¿Hay un SDK para JavaScript?

No. El SDK es solo para Python. Para otros lenguajes, exporta trazas OpenTelemetry a `POST /v1/traces`, siempre que sigan las convenciones GenAI. Consulta la [ingesta OpenTelemetry](/es/docs/instrumentation/opentelemetry#other-languages).

### ¿Puedo borrar trazas antiguas?

Todavía no. No hay endpoint de borrado ni política de retención, así que las trazas se conservan hasta que borres filas de la base de datos tú mismo.

### ¿Por qué mi script corto no muestra ninguna ejecución con OpenTelemetry?

El exportador envía los spans en segundo plano. Llama a `provider.shutdown()` (o a `force_flush()`) antes de que el script termine. Consulta [Solución de problemas](/es/docs/troubleshooting).

## Instalación

### ¿Puedo instalar solo el SDK sin el servidor?

Sí. Cada paquete es independiente:

```bash
pip install trace-agent-sdk
# o, con uv
uv add trace-agent-sdk
```

El SDK envía los eventos a cualquier servidor de TraceAgent en ejecución: no necesitas instalar el servidor en la misma máquina.

### ¿Funciona con entornos virtuales?

Sí. Recomendamos usar `venv`, `conda` o `uv` para gestionar tu entorno de Python.

## Servidor

### ¿Qué bases de datos son compatibles?

- **SQLite** (por defecto): sin configuración, ideal para desarrollo
- **PostgreSQL**: recomendada para despliegues en producción

### ¿Cómo cambio la base de datos?

Define la variable de entorno `TRACE_AGENT_DATABASE_URL`:

```bash
# PostgreSQL
TRACE_AGENT_DATABASE_URL=postgresql://user:password@localhost:5432/traceagent

# SQLite (por defecto)
TRACE_AGENT_DATABASE_URL=sqlite:///./trace_agent.db
```

## Solución de problemas

<CatIllustration state="error" size="level2" caption="¿El sistema se porta mal? Vamos a depurarlo." />

### La UI no se conecta al servidor

1. Comprueba que el servidor está en marcha: `curl http://localhost:8000/health`
2. Verifica que `TRACE_AGENT_SERVER_URL` apunta al host correcto
3. Si usas Docker, asegúrate de que los servicios están en la misma red

### Veo errores de «connection refused»

El servidor no está en marcha o está en otro puerto. Comprueba:
- ¿Está en ejecución el proceso del servidor?
- ¿Está libre el puerto 8000?
- ¿Estás detrás de un cortafuegos o de un proxy?

### Los eventos no aparecen en la UI

1. Verifica que el SDK apunta a la URL correcta del servidor
2. Comprueba que se llamó a `run.finish()`
3. Actualiza la UI: algunas vistas necesitan recargar la página

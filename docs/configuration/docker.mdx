# Docker Deployment

TraceAgent provides pre-built Docker images for the server and UI.

## Images

| Component | Image |
|-----------|-------|
| Server | `ghcr.io/lixussoftware/trace-agent-server:0.8.0` |
| UI | `ghcr.io/lixussoftware/trace-agent-ui:0.8.0` |

| Port | Component |
|------|-----------|
| `8000` | Server API (and the OpenTelemetry receiver) |
| `8080` | UI |

The images are published with the tags `0.8.0` (exact release), `0.8` (patch updates) and `latest`. Use the **same version** for the server and the UI, and pin `0.8.0` in production. `latest` is not downloaded again by itself: `docker compose up` reuses your local copy, so run `docker compose pull` (or set `pull_policy: always`) to update. See [Running in Production](/docs/configuration/production).

## Docker Compose

Create a `docker-compose.yml` to run both services:

```yaml title="docker-compose.yml"
version: "3.8"

services:
  server:
    image: ghcr.io/lixussoftware/trace-agent-server:0.8.0
    ports:
      - "8000:8000"
    environment:
      - TRACE_AGENT_DATABASE_URL=sqlite:///./data/trace_agent.db
      - TRACE_AGENT_AUDIT_METRICS_ENABLED=true
    volumes:
      - trace-data:/app/data

  ui:
    image: ghcr.io/lixussoftware/trace-agent-ui:0.8.0
    ports:
      - "8080:8080"
    environment:
      - TRACE_AGENT_SERVER_URL=http://server:8000
    depends_on:
      - server

volumes:
  trace-data:
```

```bash
docker compose up -d
```

The UI will be available at `http://localhost:8080` and the server API at `http://localhost:8000`.

## OpenTelemetry Receiver

The server container also receives OpenTelemetry traces on the same port, at `http://localhost:8000/v1/traces`. No extra port or service is needed: point your agent's OTLP exporter at that URL. See [OpenTelemetry Ingestion](/docs/instrumentation/opentelemetry).

To tune or turn off the receiver, add these to the `environment` of the `server` service:

```yaml
    environment:
      - TRACE_AGENT_OTLP_ENABLED=true
      - TRACE_AGENT_OTLP_MAX_BODY_BYTES=10000000
```

## With PostgreSQL

For production deployments, use PostgreSQL instead of SQLite:

```yaml title="docker-compose.prod.yml"
version: "3.8"

services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: traceagent
      POSTGRES_USER: traceagent
      POSTGRES_PASSWORD: changeme
    volumes:
      - pg-data:/var/lib/postgresql/data

  server:
    image: ghcr.io/lixussoftware/trace-agent-server:0.8.0
    ports:
      - "8000:8000"
    environment:
      - TRACE_AGENT_DATABASE_URL=postgresql://traceagent:changeme@db:5432/traceagent
    depends_on:
      - db

  ui:
    image: ghcr.io/lixussoftware/trace-agent-ui:0.8.0
    ports:
      - "8080:8080"
    environment:
      - TRACE_AGENT_SERVER_URL=http://server:8000
    depends_on:
      - server

volumes:
  pg-data:
```

:::danger
Change the default `POSTGRES_PASSWORD` before deploying to production.
:::

:::warning[Before using PostgreSQL]
The server image does not include a PostgreSQL driver: you need to add one (for example `psycopg`). The project's tests run on SQLite, and there are no migrations, so a schema change in a newer version does not update an existing database. See [Running in Production](/docs/configuration/production).
:::

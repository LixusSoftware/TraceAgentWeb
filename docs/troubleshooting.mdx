# Troubleshooting

## `ModuleNotFoundError: No module named 'trace_agent_pydantic_ai'`

`trace-agent-sdk` alone does not include the framework integrations. Install `trace-agent-pydantic-ai` for the Pydantic AI capability, or `trace-agent-langchain` (`No module named 'trace_agent_langchain'`) for the LangChain callback. See [Installation](/docs/getting-started/installation).

## `httpx.ConnectError` when starting a run

The server is not running or the address is wrong. The SDK does not catch these errors: `start_run`, `finish` and `fail` raise `httpx.ConnectError`. Check that the server answers at `http://localhost:8000/health`. To keep your agent working when the server is down, see [When the Server Is Down](/docs/instrumentation/sdk#when-the-server-is-down).

## My runs disappear when I recreate the container

By default the server stores its SQLite file inside the container. Mount a volume and point `TRACE_AGENT_DATABASE_URL` to it. See [Running in Production](/docs/configuration/production#keep-your-data).

## No run appears after a short script (OpenTelemetry)

The exporter sends spans in batches in the background, and the script ended before it sent them. Call `provider.shutdown()` (or `provider.force_flush()`) before the script ends. See [OpenTelemetry Ingestion](/docs/instrumentation/opentelemetry).

## Spans arrive but no run is created

Check these two causes:

- The OTLP receiver is off (`TRACE_AGENT_OTLP_ENABLED=false`). You would get a `404` from `POST /v1/traces`.
- None of the spans has a `gen_ai.operation.name` of `invoke_agent`, `chat` or `execute_tool`. Other spans are ignored.

## The run appears twice

The same agent uses both the Pydantic AI capability and OpenTelemetry, so every call is recorded twice. Pick one. See [Hooks or OpenTelemetry?](/docs/instrumentation/hooks-vs-opentelemetry).

## The run stays `running`

- With the Pydantic AI capability, you open and close the run. If the agent raised an exception, call `run.fail(...)`. See [Pydantic AI Integration](/docs/instrumentation/pydantic-ai).
- If the agent process dies, the server closes the run by itself as `failed` (error code `RunAbandoned`) after one hour without activity. To close it sooner, call `POST /api/runs/{id}/fail`. The timeout is `TRACE_AGENT_RUN_INACTIVITY_TIMEOUT_SECONDS`; an agent that stays silent for longer (for example, one very slow model call) would be closed too, so raise it in that case.
- With OpenTelemetry, a run ends when its `invoke_agent` span ends. If the library emits only `chat` spans, the run is created but never marked as finished.

## Decisions is empty while a run is running

This is normal. Decisions (tool choice, retry, recovery) appear when the run finishes.

## The UI shows no runs, or answers 502

The UI cannot reach the server. Check that the server answers at the address the UI uses (`TRACE_AGENT_SERVER_URL`, which is `http://server:8000` in the Compose file), and open `/health` on both the UI (port 8080) and the server (port 8000). When the server is unreachable, `/api/*` on the UI answers `502` with a message like `The TraceAgent server at <url> is not reachable (ConnectError).` Use the same version for the server and the UI: the UI of 0.2.x and earlier could not load runs.

## I updated the images but the UI looks old

`docker compose up` reuses the local copy of an image. Run `docker compose pull`, then `docker compose up -d` again.

## The server is down and my agent is slow or prints a warning

Tracing never stops the agent. After a failed delivery, TraceAgent prints one line (`could not deliver trace data ... The agent is not affected.`) and pauses sending for `failure_cooldown` seconds (30 by default). Events produced meanwhile are dropped.

## Pip reports a conflict with `openai`

The server accepts `openai>=1.52,<4`, so it installs next to `pydantic-ai-slim[openai]`. If you still see a conflict, upgrade `trace-agent-server`.

## Pydantic AI prints a Logfire banner

It is unrelated to TraceAgent. Set `PYDANTIC_AI_NO_BANNER=1` to hide it.
